3. Typography

Typeface: one system font stack - system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif (Segoe UI on Windows, San Francisco on macOS). Nothing is downloaded, so the app stays fully offline. Monospace: ui-monospace, Cascadia Mono, Consolas for IPs and codes. Tabular numbers are on everywhere so counters do not jump.

4. Buttons

Link styled as button
  • Primary (flat accent #3b5bdb, white text ≥ 5.6:1): one main action per form, e.g. Sign in, Generate report, Save.
  • Secondary (outlined, neutral): filters, test actions, reversible actions.
  • Destructive (solid red): disabling a user; always behind a confirmation dialog.
  • Icon-only buttons always carry an aria-label; buttons are 32-40px tall, 6px radius, and show a 2px focus ring when reached by keyboard.

Stroke icons on a 24px grid, drawn for this project. Icons are decorative (aria-hidden) and always sit next to a text label, or the button has an aria-label.

9. Layout and accessibility rules

  • Layout: 232px sidebar (Monitor / Intelligence / Administration) + sticky top bar (live status, theme switch, user, sign out) + content up to 1520px. Below 980px the sidebar becomes a slide-out menu.
  • Dashboard reading order: KPI row → threat map and latest alerts → trend charts → breakdowns → incidents and model. Two equal columns, one column below 1100px.
  • Every page starts with one H1 and a one-line subtitle separated by a rule; sections use plain H2 headings.
  • Empty states say what is missing and what to do next; tables show a loading row until data arrives.
  • "Skip to content" link, landmark regions (navigation, main), aria-current on the active page, breadcrumbs on detail pages.
  • Live status uses role="status" so screen readers announce stream changes; charts have text labels and the same data is in tables.
  • Animations respect prefers-reduced-motion. Both a dark and a light theme are provided and both pass WCAG AA.
